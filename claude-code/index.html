Claude Code Power User Guide: Getting Started

Claude Code is Claude working directly on your computer: it reads your project, edits files and runs commands. This gets you from zero to your first real task in about 30 minutes on a Windows PC.

App or terminal

This guide takes the terminal route: one install, and every power-user feature below works. If you'd rather not use a terminal yet, the Claude desktop app's Code tab runs the same Claude Code engine with nothing extra to install, and your project settings and CLAUDE.md files carry over if you switch later.

Desktop app (Code tab)Terminal (claude)
SetupNothing extra: the app includes Claude CodeOne install command
Best forVisual diffs, several sessions side by side, getting startedScripting, hooks, automation, power use
Chat tab vs Code tabThe Chat tab cannot work in your project folders. Use CodeAlways works in the folder you start it in

You need a paid plan (Pro, Max or higher). The free claude.ai plan does not include Claude Code.

Already building apps in artifacts?

Artifacts are a great sketchpad. Claude Code is where those apps become real ones on your PC:

In an artifactWith Claude Code
The app lives in a chat and is regenerated each timeReal files in a folder you own, saved in git, nothing lost
One page; outside access is limitedA real backend, a database, files on disk, any library
Edits mean asking for a new version of the whole thingClaude edits only the lines that change, across many files
Runs only on claude.aiRuns on your PC, a phone on your network, or a free host online

A good first project: take your favorite artifact app, copy its code into a new folder, start claude there and ask it to turn it into a proper project you can run locally.

Install on Windows

The recommended setup is two pieces: WSL (Linux running inside Windows) and Git (saves every version of your work). It takes one restart. Claude Code also runs on plain Windows, but WSL is what power users run: Linux tools work best there, and only WSL 2 supports Claude Code's sandboxing.

Each grey box is one command: tap its Copy button (or select it and press Ctrl+C), paste it where the step says, and press Enter.

Part 1: WSL

  1. Press the Windows key, type powershell, right-click Windows PowerShell and choose Run as administrator. Click Yes when Windows asks.
  2. In the blue window, paste this (Ctrl+V or right-click) and press Enter:
wsl --install
  1. When it finishes, restart the PC.
  2. After the restart, an Ubuntu window opens by itself (if not: Windows key, type ubuntu, click it). It asks for a username: type a short lowercase name, like alex.
  3. It asks for a password. Nothing shows on screen while you type it. That's normal. Type it, press Enter, type it again. Write it down: you'll need it when installing things.
  4. The line now ends in $. That's your Linux terminal. From now on, "open Ubuntu" means Windows key, type ubuntu, click it.

Part 2: Git and Claude Code (in the Ubuntu window)

  1. Install Git. It asks for the password from Part 1 (invisible again):
sudo apt update && sudo apt install -y git
  1. Install Claude Code. It shows little while it downloads; wait for the $ to come back:
curl -fsSL https://claude.ai/install.sh | bash
  1. Close the Ubuntu window, open a new one, and check it worked:
claude --version
  1. You should see a number like 2.1.211 (Claude Code). Done.

If something goes wrong

  • "claude: command not found": close Ubuntu, open a new window, try again.
  • wsl --install says virtualization is off: it needs a setting in the PC's BIOS. Ask Claude in the desktop app: "how do I enable virtualization on my motherboard?" with the motherboard name.
  • Red error text anywhere: drag over it with the mouse, press Ctrl+Shift+C in Ubuntu (Ctrl+C in PowerShell) to copy, and paste it to Claude in the desktop app with "what does this mean?".

Your first session

  1. Open Ubuntu and make a project folder, then step into it:
mkdir -p ~/code/my-first-app && cd ~/code/my-first-app
  1. Start Claude:
claude
  1. The first time, it asks you to sign in. If your browser doesn't open by itself, hold Ctrl and click the link it shows. Approve, then come back to Ubuntu.
  2. Let Claude learn the project. Type this and press Enter:
/init
  1. Claude writes CLAUDE.md: notes it reads every time you start. Ask Claude to add your own rules to it any time, like "explain things simply".
  2. Ask for something, in plain English: "make a small website that shows a countdown to Christmas", or paste in the code from one of your artifact apps and say "turn this into a real project here, and save it in git".
  3. When Claude wants to create a file or run a command, it asks first. Read the question, pick Yes with the arrow keys and Enter, or say no.

Handy keys: Esc stops Claude mid-step. Shift+Tab cycles through modes: press it until the bottom of the screen says plan mode, where Claude explains its plan before touching anything. Type / to see every command; /exit quits. Next time: open Ubuntu, cd ~/code/my-first-app, then claude.

Your files from Windows: in File Explorer, your Linux files are under Linux > Ubuntu > home > your-username > code in the left sidebar.

Habits that pay off early

  • Use git from day one. You never type git commands yourself. Just tell Claude "save this project in git" at the start, and "commit this" whenever something works. Then any mistake is one sentence from undone: "go back to the last commit".
  • Plan before big changes. Press Shift+Tab until the screen says plan mode for anything larger than a small fix, read the plan, then let it build.
  • Grow your CLAUDE.md. When Claude gets something wrong twice, add a line saying how you want it done. That beats repeating yourself.
  • Keep rules for every project in one place. ~/.claude/CLAUDE.md applies to all your projects at once. Put "explain things simply" or "never publish without asking me" there one time. Type /memory to open it.
  • Say "remember this". Claude keeps its own notes for each project and reads them next session. "Remember that the site goes live from the main branch" saves one. /memory shows what it has saved.
  • Never commit passwords. Tell Claude "never commit passwords, keys or .env files, and keep .env in .gitignore", and add that line to your CLAUDE.md.
  • Use the right model. Paid plans start on Opus, the strongest and most expensive. Type /model sonnet for everyday building to make your plan's usage last, or /model opusplan for Opus while planning and Sonnet while building.
  • Read what it asks to run. Approve commands you understand; ask "what does this do?" when you don't.
  • One task per session. Start a fresh session (/clear) when you switch topics; long mixed sessions get muddled.
  • Free course: Claude Code 101 on Claude Academy.

Bypass mode: how power users run it

By default Claude asks before every command and file change. That's right for your first week. After that, the prompts become most of what you do, and power users switch to bypass permissions mode: Claude just works, start to finish, and you check the result.

ModeWhat happensWhen
DefaultAsks before edits and commandsYour first projects, while you learn what Claude does
AutoRuns without routine prompts; a safety check reviews each action firstThe middle step, once prompts get tedious
BypassNo prompts at allOnce your safety net (below) is in place

To start Claude in bypass mode:

claude --dangerously-skip-permissions

The scary name is on purpose: Claude can then change or delete anything your user account can. Anthropic's docs recommend it only in isolated setups like containers or virtual machines, and point to auto mode as the safer way to cut prompts. Power users run it anyway, with a safety net instead of prompts:

  • Git and GitHub on every project, so any change is one "go back to the last commit" from undone, and a dead PC loses nothing.
  • A hook that blocks publishing (putting a site live, pushing to the main branch) until you say yes. Bypass skips prompts, not hooks.
  • Passwords in the vault, not in project files Claude reads and might paste somewhere.
  • Work inside WSL, so Claude is working in Linux, not loose across your Windows files and games.

A few things still stop and ask even in bypass mode, such as deleting your whole home folder. In a session, Shift+Tab switches between modes; bypass appears there only if you started with the flag. More: permission modes.

Running several sessions at once

Once you have more than one project, run one Claude session per project, side by side. Each one keeps its own conversation and its own CLAUDE.md, so they never mix up which project they're in.

The simple way: one window per project

  1. Open Ubuntu, cd into a project, run claude.
  2. Open another Ubuntu window for the next project, and do the same.
  3. Give each a name so you can tell them apart: type /rename and a short name, like /rename website.
  4. With tmux (see Tools to add next), each session gets its own tmux window instead and keeps running after you disconnect.

Two sessions on the same project would edit the same files and trip over each other. Ask Claude to "work in a git worktree": each session then gets its own copy of the project and merges back when done.

One screen for all of them: run claude agents to see every session, what it's doing, and which ones are waiting on you. It's a research preview, so expect changes.

Sessions talking to each other

Your sessions can message each other. It's built in and on by default in recent versions, inside WSL too. One session can tell another what it changed, ask it a question, or hand it a job, without you copying and pasting between windows.

Just ask in plain words:

  • "Tell the website session that the API now returns dates in a new format."
  • "Ask @backend whether the database change is finished." Type @ and the first letters of a session's name to pick it.
  • "Let me know when the backend session finishes what it's doing."

Type /list-agents to see which sessions this one can reach.

Good to know

  • A message is never your permission. If another session asks for something risky, you still get the yes/no prompt. One session can't approve things for another.
  • Run them all the same way. A session in bypass mode holds each message from a normal session until you approve it, and a normal session does the same for messages from bypass sessions. Run every session in bypass, or none.
  • Keep them on the same side. A session in Ubuntu (WSL) can't message one running in plain Windows. Run them all in Ubuntu.
  • Other machines: sessions on another PC or in the cloud can be reached when both use Remote Control (see the next section).
  • Every session uses your plan's usage. Five busy sessions burn through it about five times faster than one.

Working on your home PC from anywhere

Three tools, from easiest to most complete. Most people end up using all three.

ToolWhat it gives youCost
Remote Control (built into Claude Code)Keep driving a Claude Code session on your PC from your phone or any browser: type /remote-control in the session. Nothing to set up on your networkIncluded
TailscaleA private network between your phone, laptop and PC. Open the apps you build on your PC from your phone, SSH in, no ports opened to the internetFree for personal use
Sunshine + MoonlightYour full desktop on your phone, tablet or laptop, smooth enough to stream games tooFree

Install Tailscale first: Sunshine and SSH both work best over it, and it keeps your PC off the open internet.

Setting up Tailscale

  1. On the PC, download Tailscale for Windows from tailscale.com/download, install it, and sign in (a Google or Microsoft account works).
  2. On your phone, install the Tailscale app and sign in with the same account.
  3. Both devices now show in the Tailscale app. They can reach each other from anywhere, without opening anything to the internet.
