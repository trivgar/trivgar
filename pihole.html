Pi-hole + Unbound

Blocks ads and tracking on every phone, laptop and TV in your house at once, with nothing to install on any of them. It runs on a Raspberry Pi, a cheap computer about the size of a deck of cards. This is how I set mine up.

Last checked Sept 2026 · Pi-hole v6 · Debian 12 (Bookworm)

What it does

Every time a phone or TV loads something from the internet, it first has to ask where that thing lives. It's like looking up a number before you make a call. One news article can set off dozens of these lookups: one for the story, and the rest for the ads, trackers and analytics that ride along with it.

Pi-hole becomes the phone book for your whole house. When a device asks for the number of a known ad or tracking company, Pi-hole says there's no such number, and that piece of the page never loads. The article still does. It works from a list of about 1.7 million known ad and tracking addresses, and the day I looked, mine turned away 4,783 requests.

Because it works for the whole network, it covers the things you can't put an ad blocker on: smart TVs, game consoles, apps on your phone. The technical name for that phone book is DNS, and you'll see the word a lot below.

Unbound is the second half, and it's about privacy. Normally every one of those lookups goes to your internet provider, or to Google if you've changed it. Either way, one company gets a running list of every site every device in your house visits. Unbound does the lookups itself, straight from the source each time, so nobody gets the whole list.

It isn't a VPN. Your internet provider can still see which sites you connect to if it wants to. It just keeps the whole list out of any one company's log.

For the technically minded, here's the path a lookup takes:

phone, TV, laptop
  → Pi-hole   :53     drops anything on a blocklist
  → Unbound   :5335   looks up the rest itself
  → the root servers, then .com, then the site's own

What you need

  • A Raspberry Pi 3B+ or newer, or any Linux box that stays on. Mine is a Pi 4.
  • Ethernet to the router. Wi-Fi works, but every lookup in the house goes through this thing, and when it drops off Wi-Fi the whole internet looks down.
  • The login for your router.

1Give the Pi a fixed address

The router is going to tell every device to ask the Pi, so the Pi's address can't move. Do this before installing anything.

The easy way is on the router: find the Pi in its device list and reserve its address. Routers call this a DHCP reservation, a static lease or a fixed IP. Nothing changes on the Pi.

To do it on the Pi instead: Raspberry Pi OS Bookworm (2023 on) uses NetworkManager. The /etc/dhcpcd.conf edit in older guides, this one included until now, does nothing on Bookworm. 

nmcli connection show      # find the wired connection's name

sudo nmcli connection modify "Wired connection 1" \
    ipv4.method manual \
    ipv4.addresses 192.168.1.10/24 \
    ipv4.gateway 192.168.1.1 \
    ipv4.dns "127.0.0.1 1.1.1.1"
sudo nmcli connection up "Wired connection 1"

Use your own numbers. The gateway is your router, usually 192.168.1.1 or 192.168.0.1 (Google and Nest Wifi use 192.168.86.1). The DNS line has the Pi ask itself first and fall back to Cloudflare, so it can still run apt on the day Pi-hole is the thing that's broken.

Over SSH, that last command moves the Pi to its new address and your session hangs. Reconnect on the new one.

2Install Pi-hole

curl -sSL https://install.pi-hole.net | bash

That pipes a script from the internet straight into bash. It's the official method, but if it bothers you, the Pi-hole docs show how to download it and read it first.

The defaults are fine. It asks for an upstream DNS provider; pick any, it gets replaced in step 4. At the end it prints a password for the web interface. Write it down, or set your own: 

pihole setpassword

3Install Unbound

sudo apt update
sudo apt install unbound

Older guides also download root.hints from internic.net. You can skip it. On Debian the dns-root-data package comes in with Unbound, and apt keeps it current.

Create the config file Pi-hole will talk to:

sudo nano /etc/unbound/unbound.conf.d/pi-hole.conf

Paste this in:

server:
    verbosity: 0

    # Localhost only. Pi-hole is what the network talks to.
    interface: 127.0.0.1
    port: 5335
    do-ip4: yes
    do-udp: yes
    do-tcp: yes

    # Set to yes if your ISP gives you working IPv6
    do-ip6: no
    prefer-ip6: no

    harden-glue: yes
    harden-dnssec-stripped: yes
    use-caps-for-id: no
    edns-buffer-size: 1232
    qname-minimisation: yes

    # Refresh popular names before they expire
    prefetch: yes
    # One thread is plenty for a house
    num-threads: 1

    # Reject outside answers that point inside your network
    private-address: 192.168.0.0/16
    private-address: 169.254.0.0/16
    private-address: 172.16.0.0/12
    private-address: 10.0.0.0/8
    private-address: fd00::/8
    private-address: fe80::/10

Restart it and ask it something:

sudo systemctl restart unbound
dig pi-hole.net @127.0.0.1 -p 5335

You want status: NOERROR and an IP address in the answer. Run it twice. The first one walks down from the root servers; the second comes out of cache in 0 msec. If dig isn't there, sudo apt install dnsutils.

Then check DNSSEC. The first of these should fail with SERVFAIL, the second should work:

dig fail01.dnssec.works @127.0.0.1 -p 5335
dig dnssec.works @127.0.0.1 -p 5335

If the first one hands back an IP address, validation isn't on.

4Point Pi-hole at Unbound

  1. Open http://<pi-address>/admin and log in.
  2. Go to Settings → DNS.
  3. Untick every provider under Upstream DNS Servers.
  4. In Custom DNS servers, enter 127.0.0.1#5335.
  5. Save & Apply.

To check it from the shell:

sudo pihole-FTL --config dns.upstreams

It should print [ 127.0.0.1#5335 ] and nothing else.

5Point the router at Pi-hole

  1. Log into the router and find its DNS setting. It's usually with the DHCP or LAN settings.
  2. Primary DNS: the Pi's address.
  3. Secondary DNS: blank, or the Pi's address again.
  4. Save. Devices pick it up when they renew their address. On a phone, turning Wi-Fi off and on forces it.

Don't put 8.8.8.8 or 1.1.1.1 in the secondary slot to be safe. Devices don't wait for the primary to fail. Plenty of them use whichever answers first, and every lookup that goes to the second one skips your blocklists.

Pi-hole can also be the network's DHCP server (Settings → DHCP), which is how mine runs. Turn the router's DHCP off when you turn this on, so there's only one. It's also the way around a router that won't let you change the DNS it hands out.

6Check it works

The dashboard at /admin should show queries climbing within a minute. From any computer on the network: 

nslookup doubleclick.net

A blocked name comes back as 0.0.0.0. For a check in a browser, ads-blocker.com/testing works.

More blocklists

The default list catches most of it. For more, firebog.net keeps a curated set, and the green ones with a tick are the least likely to break anything. Add them on the Lists page, then run Tools → Update Gravity, or pihole -g from the shell.

Every list you add is more chances for a false positive. Add a few, live with them for a week, then decide.

When something breaks

Nothing loads

Check both halves are running:

pihole status
systemctl status unbound
dig pi-hole.net @127.0.0.1 -p 5335

If you need the internet back while you sort it out, set the router's DNS to 1.1.1.1 for now.

Ads still showing

  • Look at the router's secondary DNS again.
  • The device may be holding old answers. Toggle its Wi-Fi, or restart the browser.
  • YouTube and Twitch serve ads from the same servers as the video. DNS can't block one without the other.
  • Some hardware ignores your DNS and goes straight to Google's. Chromecasts are the usual example.

A site or app broke

Open the Query Log, find what got blocked around the time it broke, and hit Allow on the one that looks responsible. Or from the shell: 

pihole allow example.com
