Tesla + Home Assistant

Our car warms itself up before I walk out to it: before the school run, before I leave work, and half an hour before anything on the family calendar. At 9 at night it tells me if it's unplugged or unlocked. None of that needs anyone to open the Tesla app. This is how I set it up, and every automation, ready to copy.

Last checked Nov 2026 · Home Assistant 2026.10 · Tesla HTTP Proxy 2.3.0 · Tesla Custom Integration 3.24

What it does

Home Assistant is free software that runs the smart stuff in a house: lights, locks, thermostats, vacuums. You give it rules like "when this happens, do that", and it carries them out on its own. Ours runs on a Raspberry Pi, a cheap little computer that sits on a shelf.

A Tesla can be one more thing it controls. Home Assistant can read the battery, where the car is, the inside and outside temperature, and whether it's locked or plugged in. It can also send it commands: turn on the heat, turn on the seat heaters, lock the doors, change the charge limit.

Put those together and the car looks after itself. Some of what ours does:

  • Warms up on school mornings, and when I unplug my phone to leave for work.
  • Warms up 30 minutes before any family calendar event that has an address.
  • Asks me at 3:30 if I want it warm now, in 30 minutes or in 45.
  • Warms up when I've been in the grocery store for half an hour.
  • Picks the cabin temperature, seat heat and steering wheel heat from the weather.
  • At 9 PM, tells me if it's under 50% and not plugged in, or left unlocked, with a button to lock it.
  • Charges to 90% the night before a long drive on the calendar, then goes back to 80%.

The hard part is the setup. Tesla makes outside software prove who it is before the car will take a command, so you need a small piece of extra software and a public web address for the car to check. That's most of this page. Once it's done, the automations are the easy part.

What you need

  • Home Assistant running as Home Assistant OS, the version with add-ons (Home Assistant now calls them apps). Mine is on a Raspberry Pi 5.
  • HACS, the community store for Home Assistant extras. The Tesla integration comes from there.
  • A router where you can forward a port. The car has to reach your house from the internet to check your key, every time you send it a command.
  • A Tesla account and the Tesla app, already paired with the car as a phone key.
  • A free Tesla developer account. Tesla bills its Fleet API by use, with a free allowance for personal use. Check their billing page for the current numbers.

You don't need your own website or a domain. Everything below runs on the Home Assistant box, and the web address is a free one from DuckDNS.

If you have a Tesla Wall Connector, Home Assistant has a built-in integration for it that talks to it over your own network. It's separate from all this and much easier.

How it fits together

Tesla's current system is called the Fleet API. Every command has to be signed with a key the car has been told to trust, and Tesla checks your public key at a web address you give them. Here's the path a command takes: 

Home Assistant automation
  → Tesla Custom Integration      the car's sensors and buttons in HA
  → Tesla HTTP Proxy add-on       signs the command with your private key
  → Tesla's servers → the car     the car checks the signature

the internet → your router :443
  → NGINX add-on                  hands out the public key, 404 for anything else
  → DuckDNS add-on                keeps the web address pointed at your house, and the certificate valid

1Get a web address and a certificate

Install the DuckDNS add-on from the official add-on store. Sign in at duckdns.org, make a name for the Tesla key, and put it and your token in the add-on's config. If you already use DuckDNS for Home Assistant itself, add the Tesla name as a second domain. One certificate covers both.

DuckDNS add-on config
lets_encrypt:
  accept_terms: true
  certfile: fullchain.pem
  keyfile: privkey.pem
token: your-duckdns-token
domains:
  - yourname-tesla.duckdns.org
seconds: 300

On the router, forward TCP port 443 to the Home Assistant box. That's the port the car will use to fetch your key.

Port 443 open to the internet is the one real risk here. The NGINX config in step 2 answers 404 to everything except the key file, so that name shows the world nothing else. Don't point it at Home Assistant itself unless you mean to.

2Install the NGINX add-on

Install NGINX SSL proxy from the official store. The important part is customize, which tells it to load extra config files from the /share folder. The Tesla add-on drops one in there in the next step.

NGINX SSL proxy config
domain: yourname.duckdns.org
hsts: max-age=31536000; includeSubDomains
certfile: fullchain.pem
keyfile: privkey.pem
cloudflare: false
customize:
  active: true
  default: nginx_proxy_default*.conf
  servers: nginx_proxy/*.conf

The domain here is for Home Assistant's own name. The Tesla name gets its own server block from the Tesla add-on.

3Install the Tesla HTTP Proxy add-on

This one isn't in the official store. In Settings → Add-ons → Add-on store, open the ⋮ menu, pick Repositories, and add:

Add-on repository
https://github.com/llamafilm/tesla-http-proxy-addon

Install Tesla HTTP Proxy. In its config, set the domain to your Tesla name (yourname-tesla.duckdns.org) and the region (North America and Asia-Pacific share one). Leave the client ID and secret empty for now and start it.

It makes your key pair, writes the public half to /share/tesla, writes an NGINX config to /share/nginx_proxy/nginx_tesla.conf, then stops itself. That's normal. Restart the NGINX add-on so it picks up the new config. Here's what that config does, trimmed: 

server {
    server_name yourname-tesla.duckdns.org;
    listen 443 ssl http2;
    ssl_certificate /ssl/fullchain.pem;
    ssl_certificate_key /ssl/privkey.pem;

    location / {
        return 404;
    }

    location /.well-known/appspecific/com.tesla.3p.public-key.pem {
        root /share/tesla;
        try_files /com.tesla.3p.public-key.pem =404;
    }
}

Now check it from your phone on mobile data, so you're coming in from outside:

Should show a key starting with BEGIN PUBLIC KEY
https://yourname-tesla.duckdns.org/.well-known/appspecific/com.tesla.3p.public-key.pem

If that shows a certificate error or doesn't load, stop and fix it. Nothing after this works until it does.

4Register with Tesla

At developer.tesla.com, request app access. Mine went through right away. It asks for:

  • Your name as the legal entity, plus an app name, description and purpose. Anything honest works, like "Home Assistant for my own car".
  • Scopes: all of them.
  • OAuth grant type: authorization code and machine-to-machine.
  • Allowed origin: https://yourname-tesla.duckdns.org, all lowercase.
  • Redirect URI: the same with /callback on the end.

Tesla gives you a client ID and a client secret. Put both in the Tesla HTTP Proxy add-on's config and start it again. This time it stays running.

5Log in and pair the key with the car

  1. Open the add-on's web UI and tap Login to Tesla account. Sign in and allow every scope.
  2. It sends you to your /callback address, which doesn't exist, so you get a 404. That's expected. Copy the whole address from the browser bar, paste it into the add-on's web UI and tap Generate token from URL.
  3. On your phone, open the add-on's web UI again and tap Enroll public key in your vehicle. The Tesla app opens and asks to allow third-party access. Say yes. Do it for each car.

After that the car shows your key under Locks in its own screen. Delete it there and Home Assistant loses control of the car.

6Add the Tesla integration

In HACS, search for Tesla Custom Integration (alandtse/tesla), download it and restart Home Assistant. Then Settings → Devices & services → Add integration → Tesla Custom Integration. Tick the option to use the Fleet API proxy. It reads the client ID, proxy address and certificate from the add-on, so you only paste in the refresh token from step 5.

Then open the integration's options. Mine are:

  • Seconds between polling: 660, which is 11 minutes.
  • Wake cars on start: off.

Polling more often than that keeps the car awake, and an awake Tesla drains its battery sitting in the driveway. The automations below wake it on purpose when they need fresh numbers.

The integration names everything after the car. Mine is called TK-421, so everything below says tk_421. Swap in your car's name.

Make the car a person

The integration gives you a location tracker for the car. In Settings → People, add a person for the car and give it that tracker. Now the car shows up on the map like everyone else, and you can write rules like "when the car enters the grocery store zone". Add zones for the places you go in Settings → Areas, labels & zones → Zones.

If you have automations that turn the house off when everyone leaves, leave the car's person out of them. Otherwise the car parked in the driveway counts as somebody home.

The pre-heat script

Everything that warms the car calls this one script, so the rules for how warm live in one place. It wakes the car, gets fresh numbers, then skips if someone's already sitting in it or the heat is already on. Then it sets the cabin from the outside temperature, turns on the driver's seat and the steering wheel heat if it's cold, and sends a notification with a Stop button.

scripts.yaml
tesla_pre_heat:
  alias: Tesla Pre-Heat
  mode: single
  sequence:
    # The car only reports every 11 minutes and not at all asleep, so wake it
    # and ask again before trusting "nobody's in the car".
    - action: button.press
      target:
        entity_id: button.tk_421_wake_up
    - delay: "00:00:10"
    - action: homeassistant.update_entity
      target:
        entity_id:
          - binary_sensor.tk_421_user_present
          - climate.tk_421_hvac_climate_system
    - delay: "00:00:05"
    # Test for 'on', not "not off": it reads unavailable while the car sleeps.
    - if:
        - condition: state
          entity_id: binary_sensor.tk_421_user_present
          state: "on"
      then:
        - stop: Someone is already in the car
    - if:
        - condition: template
          value_template: >-
            {{ states('climate.tk_421_hvac_climate_system')
               not in ['off', 'unavailable', 'unknown'] }}
      then:
        - stop: Already heating
    - action: climate.set_hvac_mode
      target:
        entity_id: climate.tk_421_hvac_climate_system
      data:
        hvac_mode: heat_cool
    - delay: "00:00:25"
    - variables:
        t_out: "{{ states('sensor.tk_421_temperature_outside') | float(999) }}"
    - action: climate.set_temperature
      target:
        entity_id: climate.tk_421_hvac_climate_system
      data:
        temperature: >-
          {{ 76 if t_out < 50 else 72 if t_out < 65 else 68 if t_out < 75 else 66 }}
    - delay: "00:00:08"
    - action: select.select_option
      target:
        entity_id: select.tk_421_heated_seat_left
      data:
        option: "{{ 'High' if t_out < 74 else 'Off' }}"
    - delay: "00:00:04"
    - action: "switch.turn_{{ 'on' if t_out < 72 else 'off' }}"
      continue_on_error: true
      target:
        entity_id: switch.tk_421_heated_steering
    - action: notify.mobile_app_your_phone
      data:
        title: Tesla pre-heat on
        message: >-
          Outside {{ states('sensor.tk_421_temperature_outside') }}°F,
          cabin {{ states('sensor.tk_421_temperature_inside') }}°F,
          battery {{ states('sensor.tk_421_battery') }}%.
        data:
          tag: tesla_preheat
          actions:
            - action: TESLA_STOP_HVAC
              title: Stop HVAC

The delays are there because the car takes a few seconds to take each command, and sending them back to back loses some. The steering wheel uses the plain on/off switch instead of picking a heat level, because the level setting was hit and miss on mine.

I have a second copy for when the family is riding along. It's the same except it sets all five seats, High under 50°F, Medium under 60, Low under 74, and sends the notification to both of our phones.

The wake-up at the top is there for a reason. Before I added it, the car would report "nobody in the car" from whenever it last went to sleep. Someone was sitting in it in a grocery store parking lot when the pre-heat kicked in and started changing her settings.

The Stop button

The notification's Stop HVAC button needs an automation to listen for it:

- alias: Tesla Pre-Heat Stop from Notification
  mode: single
  triggers:
    - trigger: event
      event_type: mobile_app_notification_action
      event_data:
        action: TESLA_STOP_HVAC
  actions:
    - action: climate.set_hvac_mode
      target:
        entity_id: climate.tk_421_hvac_climate_system
      data:
        hvac_mode: "off"

School mornings

The simplest one. A set time on school days, only if the car is home. If one day of the week starts later, make a second copy with that day and time. 

- alias: Tesla Pre-Heat School
  mode: single
  triggers:
    - trigger: time
      at: "07:00:00"
  conditions:
    - condition: time
      weekday: [mon, tue, wed, thu, fri]
    - condition: zone
      entity_id: person.tk_421
      zone: zone.home
  actions:
    - action: script.turn_on
      target:
        entity_id: script.tesla_pre_heat

When the phone comes off the charger

My work start time moves around, so a set time doesn't work. What does work: early in the morning, my phone coming off the charger means I'm up. The Home Assistant phone app reports whether the phone is charging. Thirty minutes after it unplugs, the car starts warming up. On weekends it asks first, because unplugging on a Saturday usually doesn't mean work. 

- alias: Tesla Pre-Heat for Work
  mode: single
  triggers:
    - trigger: state
      entity_id: sensor.your_phone_battery_state
      to: discharging
      for: "00:03:00"
  conditions:
    - condition: time
      after: "05:00:00"
      before: "07:00:00"
  actions:
    - delay: "00:30:00"
    - if:
        - condition: time
          weekday: [sat, sun]
      then:
        - action: notify.mobile_app_your_phone
          data:
            title: Heading to work?
            message: It's the weekend, so the pre-heat hasn't started. Tap to start it.
            data:
              actions:
                - action: heat_car
                  title: Start pre-heat
      else:
        - action: script.tesla_pre_heat

- alias: Tesla Pre-Heat from Notification
  mode: single
  triggers:
    - trigger: event
      event_type: mobile_app_notification_action
      event_data:
        action: heat_car
  actions:
    - action: script.turn_on
      target:
        entity_id: script.tesla_pre_heat

The 3 minutes keeps a quick unplug and replug from counting.

Before a calendar event

Thirty minutes before anything on the family calendar, as long as the event has an address. "Pay the water bill" doesn't need a warm car. "Dentist, 123 Main St" does. 

- alias: Tesla Pre-Heat Before Calendar Event
  mode: single
  triggers:
    - trigger: calendar
      entity_id: calendar.family
      event: start
      offset: "-00:30:00"
  conditions:
    - condition: template
      value_template: >-
        {{ trigger.calendar_event.location is not none
           and trigger.calendar_event.location | trim != '' }}
    - condition: zone
      entity_id: person.tk_421
      zone: zone.home
  actions:
    - action: script.turn_on
      target:
        entity_id: script.tesla_pre_heat

The car-at-home check is something I'd add if I were writing it again. Mine doesn't have it, and an event while the car is across town warms it up for nobody.

After half an hour at the store

Park at the gym or the grocery store and a 30-minute timer starts. Leave before it's up and it's cancelled. If it runs out and the car's still there, it warms up. Make the timer first in Settings → Devices & services → Helpers → Timer, with a duration of 30 minutes. 

- alias: Tesla Zone Timer Start
  mode: single
  triggers:
    - trigger: zone
      entity_id: person.tk_421
      zone: zone.gym
      event: enter
    - trigger: zone
      entity_id: person.tk_421
      zone: zone.grocery
      event: enter
  actions:
    - action: timer.start
      target:
        entity_id: timer.tesla_zone_timer

- alias: Tesla Zone Timer Cancel
  mode: single
  triggers:
    - trigger: zone
      entity_id: person.tk_421
      zone: zone.gym
      event: leave
    - trigger: zone
      entity_id: person.tk_421
      zone: zone.grocery
      event: leave
  actions:
    - action: timer.cancel
      target:
        entity_id: timer.tesla_zone_timer

- alias: Tesla Pre-Heat After Zone Timer
  mode: single
  triggers:
    - trigger: event
      event_type: timer.finished
      event_data:
        entity_id: timer.tesla_zone_timer
  conditions:
    - condition: or
      conditions:
        - condition: zone
          entity_id: person.tk_421
          zone: zone.gym
        - condition: zone
          entity_id: person.tk_421
          zone: zone.grocery
  actions:
    - action: script.turn_on
      target:
        entity_id: script.tesla_pre_heat

Every zone you add needs to go in all three. Miss it in the cancel one and the timer keeps running after you drive off.

"Leaving work?" with buttons

At 3:30, if the car is at work, my phone asks if I want it warm now, in 30 minutes or in 45. The notification stays until I answer, so I can tap Start now later. If I pick a delay and the car leaves work before it's up, it doesn't bother. 

- alias: Tesla Leaving Work Prompt
  mode: single
  triggers:
    - trigger: time
      at: "15:30:00"
  conditions:
    - condition: zone
      entity_id: person.tk_421
      zone: zone.work
  actions:
    - action: notify.mobile_app_your_phone
      data:
        title: Initiate ejection sequence from work?
        message: Start the Tesla pre-heat now, in 30, or in 45?
        data:
          persistent: true
          tag: tesla_leave_work
          actions:
            - action: TESLA_LEAVE_NOW
              title: Start now
            - action: TESLA_LEAVE_30
              title: In 30 min
            - action: TESLA_LEAVE_45
              title: In 45 min

- alias: Tesla Leaving Work Buttons
  mode: queued
  triggers:
    - trigger: event
      event_type: mobile_app_notification_action
  conditions:
    - condition: template
      value_template: >-
        {{ trigger.event.data.action in
           ['TESLA_LEAVE_NOW', 'TESLA_LEAVE_30', 'TESLA_LEAVE_45'] }}
  actions:
    - variables:
        mins: >-
          {{ 0 if trigger.event.data.action == 'TESLA_LEAVE_NOW'
             else trigger.event.data.action.split('_')[-1] | int }}
    - action: notify.mobile_app_your_phone
      data:
        message: clear_notification
        data:
          tag: tesla_leave_work
    - if:
        - condition: template
          value_template: "{{ mins > 0 }}"
      then:
        - action: notify.mobile_app_your_phone
          data:
            title: Pre-heat in {{ mins }} minutes
            message: >-
              Starting it at {{ (now() + timedelta(minutes=mins)).strftime('%-I:%M %p') }}.
        - delay:
            minutes: "{{ mins }}"
        - condition: zone
          entity_id: person.tk_421
          zone: zone.work
    - action: script.tesla_pre_heat

The first version offered Now or 15 minutes. I'd tap 15 at 3:33, the heat would start at 3:48, and I wouldn't get to the car until after 4:20. That's half an hour or more of heating an empty car. Look at when you actually leave before you pick the choices.

Short stop or long stop

The union hall is a 15-minute stop most mornings and a two-and-a-half-hour meeting some evenings. A single timer fits neither. Two triggers on the same place, with different "for" times, handle both. The short one only counts in the morning. And if I leave before either time is up, nothing happens, so there's nothing to cancel. 

- alias: Tesla Pre-Heat Short or Long Stop
  mode: single
  triggers:
    - trigger: state
      entity_id: person.tk_421
      to: Hall
      for: "00:08:00"
      id: short
    - trigger: state
      entity_id: person.tk_421
      to: Hall
      for: "02:30:00"
      id: long
  conditions:
    - condition: or
      conditions:
        - condition: and
          conditions:
            - condition: trigger
              id: short
            - condition: time
              before: "12:00:00"
        - condition: trigger
          id: long
  actions:
    - action: script.turn_on
      target:
        entity_id: script.tesla_pre_heat

to: Hall is the zone's name as it shows on the person, not zone.hall. Time the long one from when you arrive, not from when the meeting starts. I get there half an hour early, so 2 hours would have warmed it up while I was still inside.

Night check

At 9 PM, if the car is home: a reminder to plug it in if it's under 50% and not on the charger, and an alert if it's unlocked or a window, the trunk or the frunk is open. The alert has a Lock button that locks it and closes the windows. The trunk and frunk you have to shut by hand. 

- alias: Tesla Night Check
  mode: single
  triggers:
    - trigger: time
      at: "21:00:00"
  conditions:
    - condition: zone
      entity_id: person.tk_421
      zone: zone.home
  actions:
    - variables:
        battery: "{{ states('sensor.tk_421_battery') | int(-1) }}"
        problems: >-
          {%- set n = namespace(p=[]) -%}
          {%- if is_state('lock.tk_421_doors', 'unlocked') %}{% set n.p = n.p + ['unlocked'] %}{% endif -%}
          {%- if is_state('cover.tk_421_windows', 'open') %}{% set n.p = n.p + ['windows open'] %}{% endif -%}
          {%- if is_state('cover.tk_421_trunk', 'open') %}{% set n.p = n.p + ['trunk open'] %}{% endif -%}
          {%- if is_state('cover.tk_421_frunk', 'open') %}{% set n.p = n.p + ['frunk open'] %}{% endif -%}
          {{- n.p | join(', ') -}}
    - if:
        - condition: template
          value_template: >-
            {{ is_state('binary_sensor.tk_421_charger', 'off') and 0 <= battery < 50 }}
      then:
        - action: notify.mobile_app_your_phone
          data:
            title: Plug in the Tesla
            message: "It's at {{ battery }}% and not plugged in."
    - if:
        - condition: template
          value_template: "{{ problems | trim != '' }}"
      then:
        - action: notify.mobile_app_your_phone
          data:
            title: The Tesla is {{ problems }}
            message: Parked at home at 9 PM.
            data:
              tag: tesla_night_check
              actions:
                - action: TESLA_NIGHT_LOCK
                  title: Lock it

- alias: Tesla Night Check Lock Button
  mode: single
  triggers:
    - trigger: event
      event_type: mobile_app_notification_action
      event_data:
        action: TESLA_NIGHT_LOCK
  actions:
    - action: lock.lock
      target:
        entity_id: lock.tk_421_doors
    - if:
        - condition: state
          entity_id: cover.tk_421_windows
          state: open
      then:
        - action: cover.close_cover
          target:
            entity_id: cover.tk_421_windows
    - delay: "00:00:20"
    - action: homeassistant.update_entity
      target:
        entity_id: [lock.tk_421_doors, cover.tk_421_windows]
    - delay: "00:00:05"
    - action: notify.mobile_app_your_phone
      data:
        title: Tesla {{ states('lock.tk_421_doors') }}
        message: Windows {{ states('cover.tk_421_windows') }}.
        data:
          tag: tesla_night_check

This one works with the car asleep, because a parked car sends its last state before it sleeps. The second notification reuses the first one's tag, so it replaces it instead of stacking up.

Tire pressure

One alert per tire when it stays under 38 psi for 10 minutes, with all four listed. Mine run 41 to 42, so set yours a few under what you normally see. 

- alias: Tesla Tire Pressure Low
  mode: queued
  triggers:
    - trigger: numeric_state
      entity_id:
        - sensor.tk_421_tpms_front_left
        - sensor.tk_421_tpms_front_right
        - sensor.tk_421_tpms_rear_left
        - sensor.tk_421_tpms_rear_right
      below: 38
      for: "00:10:00"
  actions:
    - action: notify.mobile_app_your_phone
      data:
        title: Tesla tire pressure low
        message: >-
          {{ trigger.to_state.name }} is at {{ trigger.to_state.state | float(0) | round(1) }} psi.
          Front {{ states('sensor.tk_421_tpms_front_left') | float(0) | round(1) }} /
          {{ states('sensor.tk_421_tpms_front_right') | float(0) | round(1) }},
          rear {{ states('sensor.tk_421_tpms_rear_left') | float(0) | round(1) }} /
          {{ states('sensor.tk_421_tpms_rear_right') | float(0) | round(1) }}.
        data:
          tag: tesla_tire_{{ trigger.entity_id.split('.')[1] }}

Charge for a road trip

At 7 PM it looks at tomorrow's calendar. If anything is 100 miles or more away by road, it raises the charge limit to 90% for the night. On the next evening with no long trip, it puts it back to 80%. It only ever undoes a raise it made itself, never one I set by hand, which is what the helper switch is for.

Distance comes from the built-in Waze Travel Time integration, which you need to add first. Then make a toggle helper called Tesla Trip Charge. 

- alias: Tesla Charge to 90% Before a Long Trip
  mode: single
  triggers:
    - trigger: time
      at: "19:00:00"
  actions:
    - action: calendar.get_events
      target:
        entity_id: calendar.family
      data:
        start_date_time: "{{ (today_at('00:00') + timedelta(days=1)).isoformat() }}"
        end_date_time: "{{ (today_at('23:59') + timedelta(days=1)).isoformat() }}"
      response_variable: tomorrow
      continue_on_error: true
    - variables:
        places: >-
          {%- set n = namespace(p=[]) -%}
          {%- for cal in ((tomorrow if tomorrow is defined else none) or {}).values() -%}
            {%- for e in cal.events -%}
              {%- if e.location and e.location | trim -%}
                {%- set n.p = n.p + [{'what': e.summary, 'where': e.location | trim}] -%}
              {%- endif -%}
            {%- endfor -%}
          {%- endfor -%}
          {{- n.p[:5] -}}
    - repeat:
        for_each: "{{ places }}"
        sequence:
          - action: waze_travel_time.get_travel_times
            data:
              origin: zone.home
              destination: "{{ repeat.item.where }}"
              region: us
              units: imperial
            response_variable: route
            continue_on_error: true
          - if:
              - condition: template
                value_template: >-
                  {{ route is defined and route.routes | default([]) | count > 0
                     and route.routes[0].distance >= 100 }}
            then:
              - if:
                  - condition: numeric_state
                    entity_id: number.tk_421_charge_limit
                    below: 90
                then:
                  - action: number.set_value
                    target:
                      entity_id: number.tk_421_charge_limit
                    data:
                      value: 90
                  - action: input_boolean.turn_on
                    target:
                      entity_id: input_boolean.tesla_trip_charge
                  - action: notify.mobile_app_your_phone
                    data:
                      title: Charging the Tesla to 90%
                      message: >-
                        {{ repeat.item.what }} tomorrow is
                        {{ route.routes[0].distance | round(0) | int }} miles away.
              - stop: Long trip tomorrow
    - if:
        - condition: state
          entity_id: input_boolean.tesla_trip_charge
          state: "on"
      then:
        - action: number.set_value
          target:
            entity_id: number.tk_421_charge_limit
          data:
            value: 80
        - action: input_boolean.turn_off
          target:
            entity_id: input_boolean.tesla_trip_charge

It checks up to five events with addresses, so a busy day doesn't turn into dozens of Waze lookups.

Proxy down alert

If the Tesla HTTP Proxy add-on stops, every command from Home Assistant fails without a word, and you find out when you get into a cold car. The add-on has a "running" sensor. Turn it on in Settings → Devices & services → Supervisor, under the add-on's entities, then: 

- alias: Tesla HTTP Proxy Down
  mode: single
  triggers:
    - trigger: state
      entity_id: binary_sensor.tesla_http_proxy_running
      to: "off"
  actions:
    - action: notify.mobile_app_your_phone
      data:
        title: Tesla HTTP Proxy down
        message: Tesla commands from Home Assistant will fail until it's back.

When something breaks

The numbers are old

They usually are. At 11-minute polling, anything the car reports can be up to 11 minutes old, and much older while the car is asleep, which is most of the time it's parked. That's why the pre-heat script wakes the car and asks again before it decides anything. Check the car's last-updated time in Home Assistant before you trust a reading.

"User present" says unavailable

That's the car being asleep, not broken. Anything that checks whether someone is in the car should test for on. If you test for "not off", unavailable gets through the wrong way.

Commands do nothing

  • Check the Tesla HTTP Proxy add-on is running. Its log usually says why if it isn't.
  • Load the public key address from your phone on mobile data. If the certificate expired, DuckDNS lost track of your home IP, or the router dropped the port forward, the car can't check your key and refuses every command.
  • Check your key is still listed under Locks on the car's screen.

The data stopped updating

The integration renews its login token by itself, so the expiry date on the token isn't the thing to watch. Watch the last-updated time. If it stopped moving and the car isn't just asleep, reload the integration, and if that doesn't help, generate a new refresh token from the add-on's web UI the way you did in step 5.

The battery drops while parked

Something is keeping the car awake. Usually it's polling set too short, or an automation that wakes it too often. Each wake also counts against your Fleet API allowance.
